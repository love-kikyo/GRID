# 四模型发布候选：维护入口

这里只准备 **SID / Listwise / Pointwise / Separate**，SIM、LIGER 留在内部。`public/` 是导出模板，链接按导出后的目录布局编写；用户实际审阅应打开导出目录的 README。这不是自动发布工具，不连接远程仓库。

## 唯一导出清单

`manifest.json` 逐文件指定 `source → target`，不使用递归目录或通配符。包括模型共享源码、五个训练配置、数据/评估脚本、对应测试、历史依赖锁、原许可声明和精简文档。**没有列入清单就不导出**。

不会导出：本仓库 Git 历史、根目录集群 launcher、内部 docs/台账、历史归档、SIM/LIGER、data、logs、outputs、权重、逐用户预测或凭据。共享的上游基础组件暂不做激进删减；没有完成依赖闭包验证的组件不能仅因看起来未使用就移除。

## 检查与生成

所有清单内文件与清单本身必须先提交，index、工作区字节/执行模式与 HEAD 一致。无关的内部文档改动不进入候选。导出器仅依赖标准库和 Git：

```bash
python scripts/prepare_repro_release.py --check
python scripts/prepare_repro_release.py --output /path/to/new/four-model-draft
```

输出必须是**仓库之外、父目录已存在、目标不存在**的明确路径。拒绝 symlink、路径逃逸、重复目标、数据/权重/敏感文件名及缺少许可声明的清单；先验证所有源文件，再创建目录。不会覆盖或删除已有输出；写失败保留 partial 供审阅，不能将它当作完成的候选。

`RELEASE_MANIFEST.json` 自动记录来源 commit、清单 SHA256、每个文件的来源相对路径/目标相对路径/字节数/SHA256/模式。候选不含 `.git`；来源记录不代表已运行训练或验证了原始数据。修改公开文件后必须新提交、新路径重新导出，不能手改候选再宣称其哈希仍有效。

## 发布前验收顺序

1. 审阅公开协议与模型命名；确保不夹带内部待验收结果。
2. 确认许可/资产分发边界；保留原 LICENSE / notices，不自行更换许可。
3. 完成可维护依赖锁与资源 launcher；单卡不直接替代正式三卡 batch。
4. 在兼容计算节点完成干净环境的小型端到端验收；不能在登录节点运行含 TensorFlow 的全量测试。
5. 补合法固定资产获取方式、脱敏结果与证据映射，扫描最终候选的个人路径/凭据/外链。
6. 作者确认后才创建/推送远程仓库。不要直接把内部 Git 仓库改为公开；若决定发布历史，需另做全历史安全审计。

公开门槛及依赖现状见 [模板说明](public/docs/RELEASE_GATES_ZH.md)。内部存储整理、保留策略与待确认清理对象见 [整理记录](../docs/REPOSITORY_PREPARATION_ZH.md)。
